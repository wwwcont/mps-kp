# Программы КМ-3: как писать и проверять (гайд для людей и ИИ)

ТЗ-2026, разд. 2.2 и рис. 7: три программы на ассемблере 8051 для робота кафедры (10.3.170.2:8051, после 7-й недели).
Какие именно три — зависит от варианта: `make try G=<группа> M=<номер>` → `params.md`, раздел «Программы»,
или `bin/mpscode` пишет это в заголовке отчёта. Минимум для КМ-3 — программа 1 (клавиатура).

Здесь — как писать их так, чтобы они работали на **нашей** схеме (её строит `internal/schgen`), и как проверить
до отправки: `mpscode` собирает программу своим ассемблером, проверяет правила робота и гоняет сценарии
во встроенном эмуляторе 8051 (`internal/emu51`, ставить ничего не надо) с моделями клавиатуры, буфера, индикатора, регистра Y2 и стробов.

> ✅ от `mpscode` — не гарантия «принято»: как проверяет робот, мы не знаем. Но ❌ почти всегда настоящая ошибка
> (или расхождение с соглашениями ниже — тогда смотри раздел «Если чекер неправ»).

## 0. Рецепт для ИИ: «напиши программы КМ-3 для студента X»

Делай по шагам, каждый шаг проверяй.

1. **Вариант.** Есть ли `students/<ник>/variant.yaml` (группа, M, ФИО)? Нет — создай по образцу `students/example-a12-14/`
   (ник латиницей, спроси у человека группу и номер M, если не сказаны). Числа варианта не считай — всё в `vars.inc`.
2. **Заготовки.** `make code-init S=<ник>` → `students/<ник>/code/prog1.a51`, `prog2.a51`, `prog3.a51` (+ `vars.inc` рядом,
   в git не идёт). В выводе — что должна делать каждая программа для этого варианта. Открой `vars.inc` и прочитай целиком.
3. **Пиши по одной программе**, каждую — до ✅, потом следующую (минимум для КМ-3 — программа 1):
   - только имена из `vars.inc` (`ADR_KB`, `KB_ROWS`, `F_EMPTY`, `PIN_Y2`, `T2_RELOAD_H`…), никаких «магических» адресов;
   - структура заготовки (рис. 7) не меняется: `%proc%` на `call`, `jmp $ ; %stop%`, заглушки на свободных векторах;
   - перед процедурой — комментарий: назначение, вход, выход, что портит; комментарии в строках — по смыслу;
   - пиши **свою** реализацию, не копируй `internal/codecheck/testdata/ref/` и чужие `students/*/code/` — одинаковый код у группы
     руководитель заметит.
4. **Проверка.** `make code S=<ник>` → читай `build/<группа>-23/<M>/code/report.md`. ❌ — чинить, ⚠️ — разобрать.
   Сообщения говорят, что именно не так (какая клавиша, какой указатель, сколько мкс).
5. **Грабли, на которые наступают все** (чекер их ловит):
   - столбцы клавиатуры после инициализации и после каждого опроса — в 0, иначе следующее нажатие не даст INT0;
   - строки при чтении маскировать: `anl A, #(1 SHL KB_ROWS) - 1` (старшие биты шины не подключены);
   - при INT0 по спаду — `clr IE0` в конце опроса (линия дёргается, пока перебираешь столбцы);
   - стек с `SP = 07h` растёт в банки 1–3 — не переключай банк регистров в обработчиках, сохраняй через push/pop;
   - Y2: сначала `movx` в регистр, потом строб в 0; перед запуском таймера — `clr TF1`;
   - длительности — только в прерывании таймера, в процедуре не ждать в цикле; процедура возвращается сразу;
   - буфер: голова — куда писать, хвост — откуда читать, заворот после `BUF_END − 1` (сравнивать оба байта адреса).
6. **Коммит.** Только `students/<ник>/code/prog*.a51` (и `variant.yaml`, если создавал). Push → Actions → **code** (≈ 30 с)
   проверит ещё раз; результаты — в ветке `results` → `<группа>-23/<M> <ФИО>/ПЗ2-K по СХЕМА-N/программы/` и на Яндекс-диске.
7. **Сдача.** Роботу отправляются `Фамилия ИО-код-n.txt` из `build/…/code/` (или из `results/…/ПЗ2-K по СХЕМА-N/программы/`) — в них уже
   вклеен `vars.inc`. Ответ робота записать в `notes/remarks.md` и `sessions/<дата>-<ник>.md`.

## 1. Быстрый старт

```sh
# один раз: Go 1.23+ — больше ничего (ассемблер и эмулятор 8051 свои)
make code-init S=<ник>          # заготовки students/<ник>/code/prog1.a51, prog2.a51, prog3.a51 (+ vars.inc рядом)
# … пишешь код …
make code S=<ник>               # проверка → build/<группа>-23/<M>/code/ (отчёт report.md, файлы для робота)
make code-try G=А-12 M=14 F=путь/к/prog1.a51   # любой файл под любой вариант (номер программы — из имени progN)
```

Без установки: закоммить `students/<ник>/code/progN.a51` и запушь — GitHub Actions → **КМ-3 программы и ПЗ2** проверит (без прав на запись — через Issue, команда `/км3`)
и положит результаты в ветку `results` (`<группа>/<M> <ФИО>/ПЗ2-K по СХЕМА-N/программы/`) и на Яндекс-диск; отчёт — на странице запуска (Summary).
Руками: Actions → «КМ-3 программы и ПЗ2» → Run workflow → ник.

Что в `build/<группа>/<M>/code/`:

| Файл | Что это |
| --- | --- |
| `Фамилия ИО-код-n.txt` | **то, что отправлять** (ТЗ: «Фамилия Инициалы-код-n», UTF-8): `vars.inc` вклеен, BOM снят, CRLF |
| `report.md` | отчёт по пунктам ✅ ⚠️ ❌ |
| `progN.lst`, `progN.hex` | листинг (адрес, байты, строка) и прошивка — для отладки |
| `progN.a51`, `vars.inc` | копия исходника и параметры варианта, на которых проверяли |

## 2. Файлы и оформление (правила робота, ТЗ разд. 2.2)

- Файлы: `students/<ник>/code/prog1.a51`, `prog2.a51`, `prog3.a51` — номер как в табл. 1 ТЗ. Кодировка UTF-8 без BOM.
- **Первая строка** — комментарий `; Фамилия И.О., А-12-23, 14, v1` (ФИО, группа, вариант цифрами, версия).
- `$INCLUDE (vars.inc)` — **все** адреса, биты, константы варианта бери оттуда (`ADR_KB`, `F_EMPTY`, `PIN_Y1`, `TICK_H`…),
  не пиши числа руками. Робот принимает один файл — `mpscode` вклеит `vars.inc` в `Фамилия ИО-код-n.txt` сам.
  Других `$INCLUDE` нельзя.
- Структура — рис. 7 (заготовки `make code-init` уже такие):
  1. `CSEG AT 0h` / `sjmp START`; на **всех** векторах 03h, 0Bh, 13h, 1Bh, 23h — либо обработчик, либо заглушка `nop` + `reti`;
  2. `START:` — инициализация (`mov SP, #07h`, режимы таймеров и прерываний, начальные значения, `CS_EN`);
  3. `call Процедура ; %proc%` — ровно одна такая строка, **на команде call**; в основной программе после инициализации
     или в обработчике прерывания (программа 1 — в обработчике INT0 по адресу 03h);
  4. `jmp $ ; %stop%` — ровно одна, «последняя команда»;
  5. дальше — процедуры, в конце константы и `END`.
- Пометки пишутся ровно `%proc%` и `%stop%` — без пробелов внутри, строчными, в комментарии той же строки, что и команда.
- В процедуре нет бесконечных циклов и ожидания таймера в цикле — длительности отсчитывает **обработчик прерывания таймера**.
- Комментарий ≤ 250 символов, имена ≤ 60. Перед каждой процедурой — многострочный комментарий: назначение, вход, выход, что портит.
  Комментарии по смыслу («опустить столбец 2»), а не перевод мнемоники («записать A по DPTR»).
- Timer2 и Watchdog не использовать (совместимость с i8051); T1, T3 — на Timer0, T2 — на Timer1; клавиатура — INT0, X2 — INT1.

## 3. Устройства на нашей схеме (что видит программа)

Все внешние устройства — через `movx` по адресам из `vars.inc`. Дешифратор CS работает только при **CS_EN = P3.4 = 1**
(после сброса он и так 1; если сбрасываешь P3.4 — верни перед `movx`).

**Клавиатура** (`ADR_KB`, одна ячейка на запись и чтение):
- запись: биты D0…D(`KB_COLS`−1) — столбцы Col1…ColN (регистр 74HC173). **0 — столбец опрашивается**;
- чтение: биты D0…D(`KB_ROWS`−1) — строки Row1…RowM через 74HC244, **0 — строка замкнута** на опрашиваемый столбец;
  остальные биты: при 3 строках D3 = 0 (вход на земле), D4…D7 — не подключены (любой мусор). **Маскируй** `anl A, #(1 SHL KB_ROWS) - 1`;
- ~INT0 = И всех строк: прерывание приходит, когда при опущенных столбцах замыкается любая строка. Поэтому
  **после инициализации и после каждого опроса все столбцы должны быть в 0** — иначе следующее нажатие не вызовет INT0;
- раскладка — рис. 4 ТЗ (4×3 при чётном M, 3×4 при нечётном), коды — табл. 3 («0»…«9» → 0…9, «Т» → 10, «С» → 11);
  раскладка рис. 4 ТЗ текстом (строки сверху вниз, столбцы слева направо; то же проверяет чекер):

  | 3×4 (нечётный M) | Col1 | Col2 | Col3 |   | 4×3 (чётный M) | Col1 | Col2 | Col3 | Col4 |
  | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
  | Row1 | 1 | 2 | 3 |   | Row1 | 1 | 2 | 3 | Т |
  | Row2 | 4 | 5 | 6 |   | Row2 | 4 | 5 | 6 | С |
  | Row3 | 7 | 8 | 9 |   | Row3 | 7 | 8 | 9 | 0 |
  | Row4 | 0 | Т | С |   |  |  |  |  |  |

  нажато две и больше или ничего (помеха) → `0FFh`;
- во время опроса линия INT0 дёргается — при запуске по спаду (`IT0 = 1`) сбрось `IE0` перед выходом, иначе будет лишний вызов.

**Кольцевой буфер** (IDT7005, `BUF_START` … `BUF_END`−1, `BUF_SIZE` = V байт). Указатели — 16-битные **адреса** XRAM
(младший байт по `HEAD_L`/`TAIL_L`, старший по `HEAD_H`/`TAIL_H`), готовые для `DPL/DPH`:
- **голова** (HEAD) — ячейка, куда пойдёт следующая запись; **хвост** (TAIL) — откуда следующее чтение;
- после `BUF_END − 1` идёт `BUF_START` (заворот); сравнивать оба байта адреса;
- начальное состояние: HEAD = TAIL = `BUF_START`, `F_EMPTY = 1`, `F_OVF = 0`;
- откуда берётся X2 (полная система, с 19.10.2026 — changelog /30, по схеме методички, прил. А): внешнее устройство выставляет X2
  на разъёме доступа к буферу и стробом даёт INT1. Буфером управляет МК: оба порта IDT выбираются `CS_buf` и получают адрес с шины
  МК; левый порт только читает (R/WL = 1), правый только пишет по WR МК, данные — с разъёма. Поэтому в обработчике INT1
  процедура записи делает `movx @DPTR,A` по адресу «головы», и в ячейку попадает **байт X2 с разъёма, а не A**. Робот проверяет
  процедуру записи по табл. 1 ТЗ («данные в A») — как будто в ячейку легло A; это та же процедура, в железе A просто не важен;
- **чтение** (чётный M): пусто → указатели и флаги не трогать (A — любое, лучше 0); иначе A = [TAIL], TAIL дальше,
  `F_OVF = 0`, `F_EMPTY = 1`, если TAIL догнал HEAD;
- **запись** (нечётный M): [HEAD] = A, HEAD дальше, `F_EMPTY = 0`; при переполнении самый старый отсчёт выбрасывается
  (TAIL дальше) и `F_OVF = 1`. Что такое «переполнен», ТЗ не уточняет — чекер принимает **обе** политики:
  - **V − 1** (методичка, с. 14; так у принятой Осиповой): запись, после которой HEAD догнал TAIL, — уже переполнение;
  - **V**: HEAD = TAIL при `F_EMPTY = 0` — буфер полон, следующая запись затирает самый старый.
  Какую политику увидел чекер — написано в отчёте; её же опиши в ПЗ2.

**Индикатор** (`ADR_IND`, регистр 74HC573): D0…D7 = сегменты a, b, c, d, e, f, g, dp (рис. 5 ТЗ).
Общий катод — 1 зажигает, общий анод (А-08, А-09, А-12) — 0 зажигает; `IND_OFF` — «всё погашено» для твоей схемы.
Табл. 2: коды 0–9 — цифры, 10 — «E», больше — погасить. Образцы (общий катод): 0 → 3Fh, 1 → 06h, 2 → 5Bh, 3 → 4Fh, 4 → 66h,
5 → 6Dh, 6 → 7Dh (или 7Ch), 7 → 07h (или 27h), 8 → 7Fh, 9 → 6Fh (или 67h), E → 79h; у общего анода — инверсия (`xrl A, #IND_OFF`).

**Регистр Y2** (`ADR_Y2`, 74HC573) и **стробы**: `PIN_Y1`, `PIN_Y2` — выводы P1, активный уровень 0, пассивный 1.
Y2 сначала записывается в регистр, **потом** строб 0 на T2 (данные должны быть в регистре к началу строба).
Для программы 3 с Y2 переменные — **`X1` и `X2`** в DSEG (`X1: DS 1`, `X2: DS 1`): чекер кладёт в них значения по имени.

Таймеры (кварц 12 МГц, 1 МЦ = 1 мкс): `TICK_H:TICK_L` — перезагрузка Timer0 на 1 мс, `Y1_TICKS`/`T3_TICKS` — сколько тиков;
`T2_RELOAD_H:L` — Timer1 на весь строб T2. Режим 1 (16 бит) перезагружается в обработчике — потеря на входе в прерывание
≈ 5–8 мкс на тик; на 3000 тиков это 0,5–0,8 % (допуск чекера 1 %). Компенсируй (прибавляй к TL0 текущее значение + поправку) или бери режим 2.

## 4. Что проверяет `mpscode`

Всегда: UTF-8, первая строка, комментарии ≤ 250, Timer2/Watchdog, сборка, файл для робота собирается в те же байты,
`%proc%`/`%stop%`, заглушки на всех векторах, описание процедуры; предупреждение, если прокомментировано меньше трети команд.

| Программа | Сценарии (ОЗУ после сброса случайное, как у настоящего МК; 12 МГц, 1 МЦ = 1 мкс) |
| --- | --- |
| 1 — клавиатура | инициализация доходит до `%stop%`, разрешены EA и EX0, столбцы в 0; каждая из 12 клавиш → код; две клавиши в строке, в столбце, вразброс → 0FFh; INT0 без нажатия → 0FFh; после каждого опроса столбцы снова в 0 |
| 2 — буфер, чтение | начальное состояние; пустой; 1 и 3 отсчёта; заворот хвоста; последний отсчёт на границе; после переполнения (сброс `F_OVF`); ничего лишнего в XRAM не пишется |
| 2 — буфер, запись | в пустой; в непустой; заворот головы; голова догоняет хвост (определяется политика V или V−1); переполнение и переполнение на границе по этой политике; запись не выходит за буфер |
| 3 — индикатор (M mod 3 = 0) | коды 0–10 → сегменты, 11 и 0FFh → погашен; гашение через T3; повторный вызов перезапускает T3 |
| 3 — строб Y1 (M mod 3 = 1) | два вызова: спад на `PIN_Y1`, длительность T1; процедура возвращается сразу (≤ 10 мс), а не ждёт конец строба; другие выводы P1 не трогаются |
| 3 — Y2 (M mod 3 = 2) | шесть пар X1, X2 (с X1 = 0 и переполнением суммы): одна запись в регистр, значение, запись раньше строба, строб T2 |

Для всех: каждое обращение `movx` — при `CS_EN = 1`; обработчики выходят по `RETI`; заглушки — ровно `nop / reti`;
у каждой процедуры есть комментарий-заголовок; переменные DSEG не занимают адреса «головы», «хвоста» и байты флагов;
обработчики таймеров сохраняют A и PSW (⚠️); в инициализации есть `mov SP, #07h` (⚠️, ТЗ разд. 2.2);
стек за все сценарии не заходит на переменные, «голову», «хвост» и байты флагов (❌); банк 1–3 при стеке с 07h (⚠️);
имена ≤ 60 символов (❌ при сборке); таймеры — по ТЗ (T1, T3 — Timer0, T2 — Timer1, ⚠️);
программа 1: при удержании клавиши обработчик не вызывается повторно (⚠️), опрос не дольше 2 мс (⚠️).
Допуски: T1, T3 — ±1 % (не меньше ±1 мс), ⚠️ при отклонении > 0,2 %; T2 — ±1 % (не меньше ±20 мкс).

Не проверяется (смотрят люди): смысл комментариев, алгоритмы и блок-схемы в ПЗ2, соответствие кода ПЗ.

## 5. Порядок работы для ИИ

1. Прочитай `AGENTS.md`, `RULES.md`, этот файл, свой `params.md` (`make try …` или ветка `results`).
2. `make code-init S=<ник>` — заготовки. Пиши **свою** реализацию: `internal/codecheck/testdata/ref/` — эталоны,
   на которых проверяется сам чекер; копировать их студентам нельзя (руководитель увидит одинаковый код у всей группы).
3. `make code S=<ник>` → читай `report.md`, чини, повторяй до ✅. ⚠️ — разбери, не игнорируй.
4. Коммить только `students/<ник>/code/*.a51` (не `vars.inc`, не `build/`). Отправлять роботу — `Фамилия ИО-код-n.txt` из `build/…/code/`.
5. Итоги — в `sessions/<дата>-<ник>.md`; ответ робота («принято» или текст ошибки) — туда же и в `notes/remarks.md`:
   это единственный способ узнать, как робот проверяет на самом деле.

## 6. Если чекер неправ

Чекер — общая память группы. Не подгоняй его под свою программу. Если уверен, что он ошибается (или робот ответил иначе):
докажи по ТЗ / ответу робота / даташиту, запиши в `docs/changelog.md` по протоколу `RULES.md`, поправь
`internal/codecheck` вместе с тестом (эталон должен проходить, «поломка» — падать: `check_test.go`) и `make test`.

Расширения Keil A51, которые понимает наш ассемблер: `AR0`…`AR7` (прямой адрес R0…R7 банка из `USING n`, по умолчанию 0 —
`push AR0`, `mov AR7, A`), `имя EQU R7`, метка с пробелом перед «:», `IF/ELSE/ENDIF`.

Устройство: `internal/asm51` — ассемблер (синтаксис A51/ASEM; байты сверяются с MCU 8051 IDE в CI —
